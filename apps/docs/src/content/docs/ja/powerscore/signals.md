シグナルは、試合についての1つのことだけを測り、ほかはすべて無視します。同じモードのほかのシグナルも例外ではありません。モードとは、シグナルのリストと、それに合うブーストのことです。PowerScore 3 には3つのモードがあり、それぞれが違う問いを投げかけます。

| モード | 問い | シグナル（上限） |
|---|---|---|
| `'classic'`（初期値） | 接戦で、終盤で、揺れ動いているか？ | 接戦度 42、終盤 38、勢い 38、リード交代 18、追い上げ 20 |
| `'blowouts'` | 誰かが独走しているか？ | 点差 50、リード維持 30、序盤の大差 25、追加点 15 |
| `'fantasy'` | 自分の選手に何か起こりそうか？ | プレーの渦中 50、ファンタジーポイント 35、あなたの選手 15 |

モードは `options.mode` で選びます。`score.signals` に出てくる id では、`closeness`、`lateGame`、`momentum`、`leadChanges`、`comeback`、そして `blowoutMargin`、`sustained`、`timing`、`pileOn`、そして `situation`、`production`、`exposure` です。

大差とファンタジーはクラシックを置き換えません。どちらもクラシックの上に成り立っているので、新しいモードで語るべきものがない試合にも、妥当なスコアが付きます。計算は[モードがクラシックとどう混ざるか](#how-the-modes-blend-with-classic)で説明しています。

## 上限の合計が満点を超える理由

クラシックの上限は合計156で、合計スコアは100で頭打ちです。100ポイントのうち60しか払い出さないスケールでは、残りの40が、頂点に届くことのない試合で無駄になります。上限の合計をキャップより大きくしておけば、すべてのポイントが生きます。リードが入れ替わり、連続得点が続く接戦の試合は、複数のシグナルがそれぞれの最大値近くに同時に積み上がり、最終ブザーのずっと前に80点台や90点台に届きます。終盤の同点に勢いが加わった真のクラシックは、100で振り切れます。退屈な試合は、どのシグナルも反応しないので、低いままです。

大差（120）とファンタジー（100）も同じです。合計値は、クラシックなら `scoreMaxSignalsSubtotal`、ほかのモードなら、そのモードでスコア化された `PowerScore` の結果にある `signalCeiling` です。

## シグナルをオフにする

`options.disabledSignals` に、その id を渡します。オンのままのシグナルは、そのモードの全範囲に再スケールされるので、1つオフにしたモードでも、早めに頭打ちになる代わりに0〜100の範囲に広がります。全部オフにすると、再スケールの基準がなくなり、どれも働きません。

```ts
scoreGame(game, context, { disabledSignals: ['momentum', 'comeback'] });
```

こうしたとき、`score.signals` の各エントリは `disabled: true` を持つので、内訳でグレーアウトできます。モードがクラシックと混ざるときは、`options.classicDisabledSignals` がクラシック自身のオフ設定のリストです。

## クラシック

2.x のモデルに、[ブーストとペナルティ](/arenaswap/docs/powerscore/boosts-and-penalties/)の見せ場のブーストを上乗せしたものです。

### 接戦度

上限: `scoreMaxCloseness`、42。

点差を競技ごとのしきい値と比べてティアを決め、そのティアに、試合がどこまで進んだかに応じた係数をかけます。曲線は最終ブザーを待たず、中盤までに値の大半に達します。式は `floor + (tierCeiling − floor) × progress^0.55` です。小さな一定の下限12は常に加点され、そのティア自身の上限で頭打ちになります。そのおかげで、最初の1分の同点でも、すでに意味のある数字になります。

ティアごとの上限は次のとおりです。

| 状態 | バスケットボール | フットボール | ホッケーとサッカー | 野球とソフトボール | 上限 |
|---|---|---|---|---|---|
| 同点 | | | | | 42 |
| 拮抗 | 5点以内 | 3点以内 | 1ゴール以内 | 1点以内 | 34 |
| 接戦 | 10点以内 | 9点以内 | 2ゴール以内 | 3点以内 | 20 |
| ぎりぎり圏内 | 18点以内 | 14点以内 | 3ゴール以内 | 5点以内 | 8 |
| 圏外 | 18点超 | 14点超 | 3ゴール超 | 5点超 | 0 |

0-0 は、通常の同点とは別に採点されます。序盤の 0-0 は、たいてい試合が競り合っているのではなく、まだ何も起きていないことを意味するからです。ホッケーは第3ピリオド以降、サッカーは後半以降の 0-0 に、満額の同点クレジットを与えます。それより前と、ほかのすべての競技では、0-0 は減額された上限22になります。

**10人。** サッカーで、1点リードを守る側が1人少ない場合、11人のチームよりはるかに失点しやすくなります。つまり、試合はスコアが示すより接戦で、その状況の間は、接戦度が4ポイント加算されます（上限42は変わりません）。レッドカードがシグナルに触れるのは、ここだけです。レッドカードブーストは別で、[ブーストとペナルティ](/arenaswap/docs/powerscore/boosts-and-penalties/#red-card)にあります。

接戦度が無視するもの: どちらがリードしているかと、スコアの絶対的な水準です。12-10 の2点差の試合も 112-110 の試合も同じに読まれます。接戦度が見るのは、いまボードにある数字だけだからです。

### 終盤

上限: `scoreMaxLateGame`、38。

接戦の試合の最終ピリオド全体にわたって、ほぼ直線的に上がります。終了間際の数秒だけで跳ね上がることはありません。緊張感は一気に訪れるのではなく、少しずつ高まります。上がっていく先の上限は、試合がすでにどれだけ接戦かで決まります。最後の1分に30点差の試合には、もう高まる緊張感が残っていないからです。

| 点差 | ブザー時点の上限 |
|---|---|
| 同点、拮抗、または接戦 | 36 |
| ぎりぎり圏内 | 22 |
| 圏外 | 15 |

同点の試合は、最後の1分に36を超えて上がり、最大38の延長戦プレブーストへ向かいます。これが、延長に向かう試合を、ただの接戦から区別します。延長戦やエキストライニングは、その中で築かれたリードがその競技の接戦の点差を超えるまで、満額の38を無条件で払います。超えたあとは、同じ点差の規定時間の試合と同じ上限になるので、10回表の5点差は、9回の5点差と同じところで頭打ちです。

野球とソフトボールにはクロックがないため、同じ接戦度でゲートされた上昇が、代わりにイニングを通して進みます。野球は6回、ソフトボールは5回から始まり、規定イニングの終わりまでに上限に達します。

サッカーは「延長戦」とは言いません。延長は*延長戦で同点*、PK戦は*PK戦*、終盤の互角の試合は*85分で同点*と表示されます。引き分けはリーグ戦の普通の結果で、延長戦への通過点ではないからです。プレブーストは引き続き適用されます。終盤の膠着は、本当に緊張感があるからです。

終盤が無視するもの: 最近の得点ペース（それは勢いの仕事です）と、その後一方的になった試合の、最初の3クォーターについての情報です。

### 勢い、リード交代、追い上げ

この3つはすべて、試合の過去のスコアのリストである `context.history` から読み取り、動き出すにはそれぞれ最低3つのスナップショットが必要です。どれも、きっかけとなる出来事で跳ね上がり、競技に応じた半減期で薄れていきます。この薄れ方のおかげで、得点の少ない競技でも、ゴールとゴールの間のラインが一定ではなく動き続けます。半減期と、競技ごとに変わるそのほかのものは、[競技とリーグの設定](/arenaswap/docs/powerscore/configuration/)にあります。

**勢い**（上限38）は、窓の中でいちばん古いスナップショットと最新のスナップショットの間の、得点差の変動を測ります。一方が10点を取り、もう一方が2点で返したなら、10-0 のランではなく、8の変動です。理由の文には両方の数字が出ます。得点差の変動は、完封とは違うからです。大きな変動の基準は競技によって変わり、バスケットボールは8点、ホッケーは2ゴール、野球は3点です。実際にどちらがリードしているかは無視します。20点負けているチームでも、窓の中で相手を上回って得点すれば、勢いが跳ね上がります。

**リード交代**（上限18）は、窓の中でリードが何回入れ替わったかを数えます。2回以上なら18ポイント、1回なら12ポイントです。同点は、それだけではリードとして数えません。追う側が同点にして、さらにリードを奪えば、1回の交代です。リードを奪い、同点にされ、また奪い返したなら、0回です。変動の大きさは無視します。入れ替わりが2回でも20回でも同じスコアです。そこまで来れば、その試合は予測できないことがすでに証明されているからです。フィードがプレーログからリード交代を数えているなら、`context.recentLeadChanges`（`{ count, lastAt? }`）を渡してください。その回数がスナップショットから分かる数より多ければ、そちらが優先され、ポーリングの間に起きた入れ替わりも拾えます。

**追い上げ**（上限20）は、窓の中でいちばん古いスナップショットで負けていたチームの変動を測ります。消した点差と、その後に奪ったリードの合計です。5点負けていたチームがいま6点リードなら、変動は11です。窓の開始時点が同点なら、加点はありません。追い上げたチームのリードが、その競技の2つ目の接戦の点差（バスケットボールなら10）を超えると、試合は大差になったと見なされ、消した点差から、そのリードを引いたものだけが数えられます。この変動は、接戦度と同じように、試合の進行度で係数がかかります。第1クォーターでリードを縮めるのは、残り2分で同じ点差を縮めるより低く評価されます。追うチームがやり遂げるのを待たず、傾向が起きている最中にスコア化します。

### シグナルではない2つの補正

クラシックは、勝利確率の補正（±5）と、コマーシャル中の減点も適用します。どちらもクラシックのパイプラインの一部で、[ブーストとペナルティ](/arenaswap/docs/powerscore/boosts-and-penalties/#win-probability-balance)で説明しています。

## 大差

接戦度を裏返したものです。大差は、試合が2スコア差（その競技の2つ目の接戦の点差）になるまでポイントを払わず、そこから圧勝に向かって満額まで上がります。

| シグナル | 上限 | 測るもの |
|---|---|---|
| 点差 | 50 | 点差を、試合が進むほど大きくなる係数で測ります。終盤の圧勝は、序盤の圧勝より確実だからです。満額になるのは、バスケットボールで30点、フットボールで28点、ホッケーとサッカーで5ゴール、野球とソフトボールで10点です。 |
| リード維持 | 30 | 履歴の窓のうち、現在のリーダーが2スコア以上の差をつけていた割合です。築いて、守ったリードが、ここで加点されます。元に戻るかもしれない連続得点は加点されません。スナップショットが3つ必要で、履歴が窓全体をカバーしてはじめて満額になります。 |
| 序盤の大差 | 25 | 序盤の圧勝は、終わりかけの圧勝より、見られる一方的な展開が多く残っています。規定時間の終わりに向けて0に下がります。点差がその競技の3つ目の接戦の点差を超えていて、`period` が分かっているときだけ加点されます。 |
| 追加点 | 15 | リーダーが、まだ突き放しています。リーダーの側の勢いだけを読むので、大きなリードにしがみついているだけのチームは、ここでは0です。スナップショットが3つ必要です。 |

大差が無視するもの: 接戦の試合がどう進んでいるかです。2スコア差以内の試合は、ここではほとんど0点です。そこで混ぜ合わせが登場します。

大差は、ポストシーズンブーストも払いません。プレーオフの大差は、すでに結果が決まっているので、ラウンドの重みは何も加えません。このモードは `paysPostseason: false` を設定しています。

## ファンタジー

あなたの選手が何をしているかをスコア化します。ロスターの選手ごとに1つのエントリがある `context.fantasy` を読むので、ロスターを渡すまでは、語るものがありません。

| シグナル | 上限 | 測るもの |
|---|---|---|
| プレーの渦中 | 50 | あなたの選手が試合のどこにいるかです。フットボール: 誰がボールを持っているか、レッドゾーン、ゴールライン、あなたのキッカーが射程内か、あなたのディフェンスが出ているか。野球: 打席、次の打者、または走者がいる中での投球。バスケットボール、ホッケー、サッカー: 試合の接戦度と終盤度。いちばん熱い選手が満額、ほかの全員が4分の1で数えられます。 |
| ファンタジーポイント | 35 | あなたの選手が最近稼いだファンタジーポイントで、リード交代と同じように薄れていきます。まとまった爆発（タッチダウン、ホームラン、ゴール）で満タンになります。マイナスのプレーは数えません。見逃したインターセプトを観るために切り替える人はいないからです。 |
| あなたの選手 | 15 | あなたの選手が何人、試合に出ているかです。1人につき5、最大15です。 |

フットボールは、誰がボールを持っているかをライブで把握できる唯一の競技です。バスケットボール、ホッケー、サッカーにはライブのコート上のデータがないので、そこでの試合に出ているロスターの選手は、試合そのものがどれだけ接戦で終盤かと同じ価値になります。`active: false`（ベンチ、負傷、退場）とマークされた選手は、数えません。

## モードがクラシックとどう混ざるか

新しい2つのモードは、どちらも単独では成り立ちません。それぞれがクラシックと組み合わされるので、静かな試合がマップから消えることはありません。

| モード | 混ぜ方 | 式 | 理由 |
|---|---|---|---|
| 大差 | 下限 | `total = max(blowouts, 0.3 × classic)` | 接戦の試合はクラシックのスコアの30%を保つので、圧勝のない夜でも、切り替える先があります。本物の圧勝は、そのどれよりも上に来ます。 |
| ファンタジー | ブースト | `total = min(100, classic + 0.6 × fantasy)` | あなたの選手の試合は、クラシックのスコアより上がることはあっても、下がることはなく、選手のいない試合はそのままクラシックです。以前の0.6/0.4の混ぜ方では、あなたの選手がいる終盤の1点差の試合が、選手のいない同じ試合より下に順位づけられていました。 |

ファンタジーの重みは `options.classicBlend` で変えられます。

```ts
scoreGame(game, context, {
	mode: 'fantasy',
	classicBlend: { kind: 'boost', weight: 0.8 },
});
```

出場中の選手が1人もいない試合は、ファンタジーが語るものがありません。クラシックとしてスコア化され、`score.modeId` は `'classic'` になるので、見分けられます。モードがクラシックと混ざるときは、いつでも `score.classicTotal` にクラシック自身の合計が入り、`score.blend` に計算の中身が入ります。`{ kind, weight, ownTotal, classicTotal, floorApplied? }` です。内訳では、これを使って、下限が勝ったときは「クラシック 70 × 30% = 21」、重み0.6でファンタジーのスコアが50なら「+30」と表示できます。

## これらの数字の出どころ

クラシックの上限は、エクスポートされた定数です。`scoreMaxCloseness`、`scoreMaxLateGame`、`scoreMaxMomentum`、`scoreMaxLeadChanges`、`scoreMaxComeback`、`scoreMaxTotal` です。大差とファンタジーの上限は、それぞれのシグナル定義である `blowoutsSignals` と `fantasySignals` にあるので、実行時に読めます。3つのモードのどれもあなたの問いに答えないなら、[`defineMode` で自作](/arenaswap/docs/powerscore/api-reference/#definemode)してください。完全なシグネチャは [API リファレンス](/arenaswap/docs/powerscore/api-reference/)にあります。
