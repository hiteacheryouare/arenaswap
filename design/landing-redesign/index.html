What came out of the codebase.

The cards, the popup, the charts and the settings rows are the shipped components with their real values, not approximations of them. A few of those values were a surprise.

  • The game card is a light card, and I had been drawing it dark .game-card is #ffffff with a #dee2e6 border. buildGameCardStyle() then paints a linear-gradient(to right, awayColor28, homeColor28) wash over the white and puts 5px of each team’s colour down the left and right edges. Four white cards against the dark hero is a much stronger picture than the dark cards in the last pass, and it is what the product actually looks like. packages/ui/src/_game-card.scss:53 · gameCardShared.tsx:105
  • Scores are set in Geist, not DM Sans DM Sans ships no tabular figures, so a 1 is under half the width of a 0 and a score pair’s optical centre drifts off the card axis. The card uses Geist for scorelines and holds a 2.4ch minimum per digit. Geist is now back in the font set for this page. _game-card.scss:45 · scoreboard-figures mixin
  • The PowerScore bar has a computed colour, not a fixed one powerScoreColor() interpolates from rgb(139,148,158) at 0 to rgb(247,92,3) at 100, so the bar warms as the game gets better. The hero animation recomputes it every frame with the same function, which is why the MLB card visibly cools as its score falls. gameCardShared.tsx:54
  • The baseball card gets the base diamond and the ball-strike-out dots Second base sits above third and first, pulled up so the three read as one cluster, and the markers are squashed to scaleY(0.74) because the glyph is square and Apple’s is not. This is the kind of detail that makes a screenshot look real, so the MLB card in the hero has it. _game-card.scss:250
  • The charts already exist, and there are four of them PowerScore over time, Game score over time, Win probability, and PowerScore components over time. The stacked one uses #22c55e, #f75c03, #2274a5, #f1c40f, #d90368, and the axes are #8b949e on rgba(71,85,105,0.34) split lines. Those are the colours in the section above. gameDetailChartOptions.ts
  • The six settings groups already have marketing copy “How eager ArenaSwap is to move you to a better game.” “Where to park you when every game goes quiet.” Those are the shipped strings, straight out of the locale file, and they are better than anything I would have written for the section. All six are used verbatim. apps/extension/locales/en.json → setup.group*
  • Demo mode exists in the product “Scripted games, so you can watch a switch happen on demand.” The extension already ships a scripted demo for exactly the reason the hero needs one, which settles the question of whether a scripted hero is honest. It is the same idea, in the same voice. settingsCatalog.ts · setup.groupDemoDesc
  • Popup labels are the real ones “Active Tabs”, “Up Next”, “Enable auto-switching”, “Settings”, “Tour”. No invented chrome. locales/en.json → main.*

One thing on that hero is not product UI, and I want to be explicit about it: the orange ring and the ON YOUR SCREEN flag on the active card. The extension has no such state, because in the extension the active tab is the browser tab. Those two marks are the page’s annotation layer.

The hero motion.

Twelve seconds, twenty frames, 600ms apart. Every score and every PowerScore is written into an array. Which card is on screen is not animated separately: it is whichever PowerScore is highest, the rule the switcher uses, so the switch falls out of the data.

  • 0:00

    Three assigned tabs, three live games. The MLB card is on screen at 78, lifted with an orange ring. A close basketball game sits at 58 and a hockey blowout sits at 22.

  • 0:00–4:48

    Scores move and the PowerScore bars move with them. The NBA game climbs from 58 as it gets close late. The MLB game slides from 78 as the Phillies pull away, and its bar cools from orange back toward grey.

  • 0:04.8

    The NBA card passes it and takes the screen. The ring and the flag move across, the old card drops flat, and the line underneath fades to “Celtics at Knicks”.

  • to 0:12

    The NBA game climbs to 88 and nothing switches again, which is the second half of the point: it moves when it should and leaves you alone when it should not.

  • Settled

    It holds the last frame instead of looping, so scores never jump backwards while somebody is reading. Reduced motion gets the settled frame immediately.

Why the numbers should not be invented

A scripted demo reads as fake the moment a number is implausible. scripts/powerscore/validateLive.ts already captures real sequences from live games, so the twenty frames should be lifted from one close game we watched rather than typed at the keyboard. That is the first build step.

What it costs

About 60 lines and no dependency. The animation reuses the shipped card markup and only writes text content and two style properties, so it cannot drift away from the component it is animating.

The slop pass.

What came out, and why. The test each element had to pass: would this exist if it were not a familiar web-design pattern.

  • Cut: the label above the hero demo It read “Four tabs, four games / watch which tab has the sound”, sitting above a strip that already has a line underneath naming what is on screen. Two labels for one object. The line underneath survived because it changes when the switch happens, so it carries information; the one above only announced.
  • Cut: the invented tab shapes The last pass drew browser-tab trapezoids with a league code and a score in them, which was a diagram of a game card standing in for a game card. Replaced with the component.
  • Cut: SOUND ON and MUTED labels on every card Four copies of a status word to communicate one piece of state. The ring and the flag on the active card say the same thing once, and muting is explained in the band below in a sentence.
  • Kept: the 31 A number set at 104px is the graphic in a design with no imagery, and it answers the question most visitors actually have. It is also the real count rather than a rounded-up one.
  • Kept: the “Free. No account.” tail It reads like a marketing flourish and it is doing real work: those are the three objections left at the bottom of the page, answered in the order people raise them.
  • Not added: a FAQ, testimonials, a logo wall, a second CTA band The page has two install buttons, at the top and the bottom, and nothing in between. The FAQ is worth keeping for search but belongs on its own page.
  • Prose: fewer em dashes, no inflated claims This document had an em dash in most paragraphs and phrases like “the whole product in one second of motion”. Both are gone. Section headings are sentence case throughout.

Release notes and docs.

Unchanged. One quiet reading shell for both, so only the homepage carries the visual idea.

Release notes.

What changed, what it was doing wrong before, and why it behaves differently now.

2.015 Aug 202688 changes since 1.4.3

PowerScore is rebuilt, the screens around it are rebuilt to match, and the extension now covers 31 leagues across six sports in 12 languages.

Scoring19 changes

A game at halftime was worth 10 points for doing nothing.

The scorer has always zeroed a frozen game. The boosts never got the memo, so a halftime game with a favorite team in it still collected its +10, enough to beat a genuinely quiet live game and take the tab.

  • Halftime, intermissions and delays score 0 no matter what boosts apply. Held back until play resumes, then paid out exactly as before.
  • The scoring-opportunity boost now respects intermissions, not just delays.

A red-zone drive while up 31 was worth as much as one in a tie game.

Settings11 changes

Twenty controls in one flat column, and none of them looked more important than any other.

Settings is now an index. Six categories, each opening a focused page that fits in one window.

Scoring a game.

One function, one game, one number. score() takes a game in whatever shape your data source hands it to you and returns a 0–100 rating of how exciting that game is right now, plus the five signal contributions behind it.

// A tied game with two minutes left.
import { score } from 'powerscore';

const result = score(game);

result.total // => 84
result.closeness // => 28

Frozen games

A game at halftime, in an intermission, or under a delay scores exactly 0, every signal and every boost together. isPlayFrozen() is exported if you need the same rule elsewhere.

Questions.

Does the site import the real components, or copy them?

The mockup above reimplements the card in CSS because it has to run standalone. The real page should import liveGameCard from @arenaswap/ui, which means the site inherits card changes for free and can never drift. It also means a card bug on the extension becomes a card bug on the homepage, so the shared surface needs the Cypress coverage it already has.

Do the charts use ECharts on the landing page?

echarts is already a docs dependency and the four options builders are already written, so the honest version is to reuse them with canned history. The alternative is static SVG like the mockup, which is a fraction of the weight on the page that most matters for load time. I would start with SVG and only reach for ECharts if the section needs interaction.

Where does the FAQ go?

It is on the current homepage and not on this one. Eight questions on leagues, streaming services, privacy and the algorithm are worth keeping for search, so I would give them a page rather than delete them.

Is 2.0 one release, or the 1.4.3 to 2.0 increments?

Still open. Everything in the changelog is V2 work, so the simple answer is one 2.0 entry holding all 88 changes. If those intermediate versions shipped to users and you want them kept, the feed can split them.
